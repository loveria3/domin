기획 — 다섯 질문으로 설계 메모 만들기

아직 만들지 마핵심7분

코워크 폴더 내작업실/검색함을 만들어 연결합니다. 빈 폴더에서 시작해요.

질문검색함의 답필요한 칸
① 무엇을 보여 줄까?찾은 소식 목록 · 보관/버림 단추 · 보관함 · 키워드🪟 웹페이지
② 무엇을 남길까?키워드 · 빼는 말 / 기사(제목 · 언론사 · 링크 · 날짜 · 상태 · 메모)🗄 데이터베이스
③ 누가 볼까?나(와 가족)만 — 비밀번호 4자리🔒 금고
④ 저절로 할 일?매일 아침 키워드로 찾아 두기🍳 서버 + ⏰ 알람
⑤ 어디에 올릴까?웹페이지는 버셀, 서버 · 데이터베이스는 내 구글 계정주소
프롬프트 1 — 설계 메모
AI교육 소식을 매일 아침 찾아 주는 웹앱을 만들 거야. 아직 코드는 만들지 마. 나에게 질문 세 개를 해서 내 키워드를 정한 뒤, 설계.txt를 만들어줘. 설계.txt에는 이것만 쉬운 말로 적어줘. 1. 화면: 탭 3개(새로 · 보관함 · 키워드), 맨 위 [지금 검색] 단추 2. 구글 시트 칸: 날짜 · 제목 · 언론사 · 링크 · 키워드 · 상태(새로/보관/버림) · 메모 · ID 3. 웹페이지가 서버에 하는 부탁 이름: 목록 · 검색 · 보관 · 버림 · 키워드저장 4. 서버의 답은 언제나 같은 모양: 성공 여부 · 기사 목록 · 키워드 · 마지막 검색 시각 5. 내 키워드 5개 · 꼭 들어갈 말 · 빼는 말
Q1. 어느 지역 교육을 찾으세요? (제주 전체 / 서귀포) Q2. 누구를 위한 교육이 궁금하세요? (시니어 · 소상공인 · 교사 …) Q3. 빼고 싶은 기사는? (AI 주식 · 행사 후기 …) → 설계.txt를 만들었어요.

💡 설계.txt는 약속 종이입니다. 뒤에서 웹페이지와 서버를 따로 만들어도, 둘 다 이 종이대로 만들게 하면 서로 말이 통해요.

오늘 가장 중요한 요령이 이것입니다. 한 번에 "검색함 만들어줘"라고 하면 사람마다 전혀 다른 앱이 나오고, 서버와 웹페이지가 서로 안 맞아 막힙니다. 시트 칸 이름 · 부탁 이름을 먼저 종이에 박아 두면 수강생끼리 결과가 비슷해져서 돌봐 주기도 쉽습니다.

웹페이지 먼저 — 가짜 기사로 화면 만들기

🪟 웹페이지코워크10분

서버는 아직 없으니 가짜 기사로 화면부터 만들어 눌러 봅니다.

프롬프트 3-1 — 화면 만들기
설계.txt대로 index.html 하나를 만들어줘. - 아직 서버가 없으니 가짜 기사 5개로 움직이게 - 맨 위에 const API_URL = ''; 한 줄을 비워 둬 (나중에 서버 주소를 넣을 곳) 모양은 이렇게 해줘. - 휴대폰 화면 폭, Pretendard 글꼴, 바탕은 연한 회녹색(#f4f6f1) - 머리: 진한 초록(#14532d) 바탕에 흰 글씨, 아래 모서리만 둥글게. 앱 이름 · 작은 글씨 '마지막 검색' · 주황(#f59e0b) [🔍 지금 검색] 단추 - 탭 3개(🆕 새로 · ⭐ 보관함 · ⚙ 키워드)는 내려도 위에 붙어 있고, 고른 탭은 초록 바탕. 탭 이름 옆에 개수 숫자 - 기사 카드: 흰 바탕, 둥근 모서리, 옅은 테두리. 굵은 제목 아래 작은 회색 글씨로 언론사 · 날짜, 키워드는 연초록 #꼬리표. 단추 [⭐ 보관]은 초록, [버림]은 회색 - 보관함: 맨 위에 찾기 칸, 카드마다 메모 칸과 [메모 저장] - 키워드 탭: 흰 상자 세 개(🔑 키워드 · ✅ 꼭 들어갈 말 · 🚫 빼는 말). 낱말은 동그란 알약 모양(빼는 말은 빨간색)에 × 단추, 아래에 입력 칸 + [추가] - 알림 창(alert) 대신 화면 아래에 잠깐 떴다 사라지는 검은 알림 - 비어 있으면 점선 상자에 "위의 🔍 지금 검색을 눌러 보세요"

💡 모양 줄은 바꿔도 됩니다. 색 번호 대신 "제주 바다처럼 푸르게"처럼 말로 써도 돼요. 완성 예시와 비슷하게 하고 싶으면 그대로 두세요.

  1. 내작업실/검색함/index.html 더블클릭
  2. ⭐ 보관 → 보관함 탭으로 옮겨 가는지 · 버림 → 사라지는지
프롬프트 3-2 — 마음에 안 들면 이어서 말하기
[예: 글씨를 더 크게 / 색을 제주 바다처럼 푸르게 / 단추를 아래로] 바꿔줘. API_URL 줄은 그대로 둬.
  • 탭 3개가 눌린다
  • 보관 · 버림이 움직인다
  • 새로 고침하면 처음으로 돌아간다 — 정상! 아직 데이터베이스가 없어서 남지 않아요
🆘 막히면 — 위의 웹페이지 완성본 ↓을 받아 검색함 폴더에 index.html로 넣고 4번으로.

세 번째 확인이 이 단계의 핵심 깨달음입니다. "새로 고침하면 사라지죠? 남기려면 무엇이 필요할까요?" → "데이터베이스!" 하고 4번으로 넘어갑니다.

서버 코드 만들기 — 찾고, 거르고, 적기

🍳 서버핵심10분

서버가 할 일은 세 가지뿐입니다. ① 구글 뉴스에서 찾기 → ② 빼는 말 거르기 → ③ 시트에 적기. 여기에 웹페이지의 부탁에 답하는 창구를 붙여요.

프롬프트 4-1 — 서버 코드
설계.txt대로 구글 앱스크립트 코드를 code.gs로 만들어줘. - setup: 시트에 '키워드' 탭과 '검색함' 탭을 만들고, 내 키워드를 넣고, 첫 검색 한 번 - 검색: 키워드마다 구글 뉴스 RSS에서 최근 7일 기사를 찾아 빼는 말이 든 제목은 버리고, 이미 있는 링크는 건너뛰고, 검색함 탭에 '새로'로 적기 (한 키워드에서 막혀도 멈추지 말고 다음 키워드로) - doPost: 웹페이지의 부탁(목록 · 검색 · 보관 · 버림 · 키워드저장)에 JSON으로 답하기 - 비밀번호는 코드에 쓰지 말고 스크립트 속성 PIN과 맞는지만 확인 - 매일 아침 알람이 부를 dailySearch 함수 맨 위에 붙여 넣는 순서를 쉬운 말로 적어줘.
프롬프트 4-2 — 붙여 넣기 전에 설명부터
code.gs가 하는 일을 쉬운 말로 다섯 줄로 설명해줘. 내 구글 계정에서 무엇을 읽고 쓰는지, 다른 곳으로 보내는 것이 있는지도 알려줘.
1. 시트에 '키워드' · '검색함' 탭을 만듭니다. 2. 키워드마다 구글 뉴스에서 기사 제목 · 링크를 가져옵니다. 3. 빼는 말이 든 기사와 이미 있는 기사는 건너뜁니다. 4. 웹페이지가 PIN을 맞게 보내면 목록을 돌려주고, 보관 · 버림을 시트에 적습니다. 5. 이 시트 말고 다른 파일은 읽지 않고, 다른 곳으로 보내는 것도 없습니다.
🆘 막히면 — 위의 서버 코드 완성본 ↓을 받아 5번에서 그 글을 붙여 넣으세요. 맨 위 DEFAULT_KEYWORDS 줄만 내 키워드로 바꾸면 됩니다.

4-2는 꼭 시키세요. 5번에서 '확인되지 않은 앱' 경고가 나올 때 "무엇을 하는 코드인지 내가 먼저 확인했으니 허용한다"는 근거가 됩니다.

클로드가 만든 코드는 수강생마다 조금씩 다릅니다. 설계.txt의 부탁 이름과 시트 칸 이름만 맞으면 괜찮아요.

(11/27 시험) 구글 뉴스를 짧은 사이에 여러 번 부르면 '429 너무 많은 요청'으로 막힐 때가 있습니다. '막혀도 다음 키워드로' 한 줄이 없으면 setup이 통째로 멈춰요. 이 줄은 지우지 마세요.
